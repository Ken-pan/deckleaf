## English introduction

I built Deckleaf, a local-first editor for project reviews, portfolios and presentations. You can edit text, images, layouts and charts, review AI proposals before applying them, and export a portable Deck file or supported presentation formats.

I made it with Codex and reviewed the generated code, dependencies and licenses. It is an early release: complex PowerPoint effects and typography need checking in the target app, and optional cloud integrations have their own setup requirements. Ordinary local editing needs no account or AI key.

The code is MIT licensed, including commercial and closed-source reuse. I'd especially appreciate a small bug report or an example of a workflow that feels awkward. Please use fictional material in public reports.

Try it: https://deckleaf-kens-toolbox.netlify.app/app?demo=1

## A small launch sequence

1. Publish the clean GitHub source and one tagged release with its archive checksum, readable README, notices and known limits. Enable private vulnerability reporting and secret protection.
2. Offer a runnable local package and an optional browser demo only after its privacy, provider and budget gates are met.
3. Share one short demonstration with an audience that already discusses presentation/design tooling. Answer concrete questions; don't post the same pitch indiscriminately.
4. Try Show HN if its current guidelines fit. Product Hunt is optional; it can wait until onboarding and the demo are reliable. A thoughtful devlog about reviewable AI edits may be more useful than a launch ranking.
5. Track useful outcomes: successful first edit/export, actionable issues and repeat users. Add analytics only after a deliberate privacy decision; this source release has none.
